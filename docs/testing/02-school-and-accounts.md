# 2. School setup, accounts and assignments

[Testing home](README.md) · Next: [Authoring and AI](03-authoring-and-ai.md)

Sign in as school administrator. Use a test prefix in names so records are easy to recognize. Keep one untouched control account for recovery.

1. **Classes.** In School setup, create Grade 9 / Section A and Grade 9 / Section B, then a Grade 10 class. Expect composed class names and separate grade/section fields. Edit an unused class and refresh: changes persist. Existing unclassified classes must not be silently assigned a guessed grade.
2. **Subjects.** Create Grade 9 Physics and Grade 10 Physics. Expect grade-specific subjects shared across sections of the same grade. A subject/class grade mismatch must not become an active assignment.
3. **Teachers.** Create two teachers using First name, Father's name and Grandfather's name. Expect immediate private credentials. New IDs use `TCH/<school number>/<teacher number>`, with school number at least three digits and teacher number at least four. Teacher numbering is separate from student numbering. Assignments should show readable full names and subjects, not teacher IDs/course codes as their main labels.
4. **Roster.** Import two students into Grade 9 A and another into Grade 9 B using the portal's supported template. Review the preview, confirm, then issue login details. Expect students under their own class cards in Accounts. Repeat a roster reference: no silent duplicate account. Invalid rows should give actionable feedback.
5. **Student IDs.** Expect `STU/SID/NNNN/YY`, for example `STU/001/0001/19`. SID is the school's stable numeric identity; YY is the Ethiopian creation year. Numbers continue across both classes, not from 0001 for each class. Existing records can make the next number higher. Old IDs remain unchanged. School renaming must not change SID.
6. **Passwords and sign-in.** Newly issued/reset directory passwords contain exactly eight characters with uppercase, lowercase, number and symbol. Sign in using a newly issued student's and teacher's exact credentials. Save any credential download privately. Closing the credential response must not expose passwords in later account listings; replay does not reveal the same passwords again.
7. **Class account browsing.** Select each class card; search and use Load more if available. Expect only that class's students. Test the unassigned group if present. Closing a credential panel should preserve the selected class.
8. **Edit/reset.** Open a student's Edit panel. Change a name, save, refresh and verify. Password reset belongs inside Edit rather than a separate prominent student-list button. Reset a disposable student's password: ID stays unchanged and the old password stops working. Unsaved profile changes must be handled before reset. An ID change revokes prior sessions.
9. **Assignments.** Assign a teacher and Grade 9 Physics to both Grade 9 sections. Filter by grade, class, subject and teacher; use search. Expect only matching assignments, with grade buttons leading to class choices. At wide widths expect two cards per row where space permits; at phone widths expect readable stacked content.
10. **Removal.** Create an unused disposable class/account/subject/assignment and use its removal control with the required reason/confirmation. Expect it to leave active lists. Delete class retains history and does not delete its student accounts. A history-bearing account is deactivated/retained rather than erasing exam evidence. Assignments used by exams may reject removal. Approved exams and official results are not freely deletable.
11. **Number continuity.** Delete an unused newly numbered student or teacher, create another and confirm the old number is not reused. Do not create thousands of accounts manually: boundary 9999→10000, rollback and concurrency belong to the isolated technical suite.
12. **Access isolation.** A teacher/student must not manage the directory. With a second synthetic school, its accounts and classes must not appear in this school's lists. Direct API isolation is also a required technical test.
