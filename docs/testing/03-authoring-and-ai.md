# 3. Teacher authoring, imports and AI

[Testing home](README.md) · Next: [Scheduling and invigilation](04-scheduling-and-invigilation.md)

Use an assigned teacher and keep the worker terminal running. Use a synthetic Word/Excel paper with known answers. Keep one valid file and one deliberately incomplete file. Local uploads requesting AI may send content to the configured external provider.

1. **Paper list.** Open My exam papers. Expect Active & upcoming and Past papers, newest created first, with status filtering. An approved paper with no sitting stays active. Create a draft using an assigned class/subject and save the title, language, duration, passing mark and instructions. Refresh: the draft persists.
2. **Templates.** Download the offered Word or Excel example, fill it according to its headings and upload it. Expect file reading to discover the intended number of questions and preserve stems, choices and answer keys. File parsing and AI explanations are separate stages: finding questions alone does not prove AI succeeded.
3. **AI explanations.** Wait for AI preparation with the worker running. Inspect several explanations against the known answers, including Amharic output if selected. Expect explanations to correspond to their questions and language; wrong or conflicting suggestions need review rather than automatic acceptance. Key presence does not prove provider availability.
4. **Failure/retry.** Use a controlled provider failure in the technical environment, or record an actual failure. Expect an actionable needs-attention state, preserved parsed questions, and Retry AI preparation when eligible. Retry must not duplicate questions or overwrite later teacher edits. The previous live probe passed Groq but did not establish Gemini fallback availability; test fallback separately.
5. **Queued cancellation.** In this isolated local environment, stop only the worker with Ctrl+C, upload into a disposable draft and cancel/remove the import with a reason. Expect the waiting state to clear and another upload to be allowed. Restart the worker. The cancelled job must not later replace questions. Repeat during processing on another disposable draft.
6. **Retained questions.** Cancel an import after questions were read. Expect parsed questions to remain; removing a whole editable draft is a separate action. A provider request already sent may finish externally, but cancelled work must not be committed as new output.
7. **Review and warnings.** Compare a complete question with one missing an answer or containing an unresolved conflict. Expect meaningful warnings only where needed. Confirm all questions without warnings should review eligible questions in one action. It must not approve incomplete/conflicting questions. Review is not universally optional: required valid reviewed content still gates submission.
8. **Edit and save.** Change a question and answer key, save, then refresh. Expect the revision to persist and review state to be invalidated as appropriate. A late AI response must not undo your edit. Resolve warnings before submission.
9. **Mobile editor.** At 360-pixel width, open a question card, enter a long stem/answer and use Previous question/Next question. Expect usable fields rather than two-character-wide columns. Unsaved changes must be protected before moving to another question. At desktop, the overview remains usable. There should be no duplicate review shortcut serving the same action.
10. **AI generation, if enabled.** Have the administrator configure the school's permitted AI-generation policy. Use the existing generation controls with a small synthetic request. Verify eligibility/quota/assignment errors, progress, cancellation and generated question review. Disabled generation must not bypass school policy. Provider quality/quota acceptance is separate from mocked automated tests.
11. **Submit/return.** Submit the valid reviewed paper for approval. Expect it in the administrator's queue. Have the administrator return it with a comment; verify the teacher can see the comment, edit and resubmit. Resubmission should enter the queue using its latest submission time.
12. **Remove draft.** Remove a disposable editable draft. Expect it to disappear without later worker revival. Approved papers should not offer unrestricted deletion.
