## What the backend developer must do

Implement the read contracts, audited approval/return, approved-version package preparation, roster snapshot, scheduling and safe rescheduling below. Connect the teacher submission queue to the administrator and the approved sitting to the existing student API. Use src/features/exams/admin/schemas.ts and api.ts as executable wire references. Run every acceptance case and return the report below. Report concrete blockers with evidence; do not choose different interfaces or ask whether to implement the requirements.

## Access and common rules

All routes use /api/v1, completed school-admin MFA, school isolation, private no-store responses, allowed Origin and session-bound CSRF. Other roles get 403. Foreign-school IDs get 404. Every mutation requires a retained UUID Idempotency-Key scoped to school, actor and operation. Authenticate first, then replay the original response for an identical canonical payload before checking old revisions/time. Changed payload with the same key is 409 REVISION_CONFLICT. Store replay records durably for the academic-record lifetime. Row locks, transactions and uniqueness constraints govern decisions and schedules; the frontend checkbox is not authorization.

## Administrator reads

GET /admin/exams?limit=25&cursor=... returns `{items:[Summary],nextCursor,serverNow}`. Same common pagination bounds; sort by first-created exam timestamp descending, examId descending, stable cursor. Include same-school submitted, returned and approved exams; never expose another school's keys. Teacher drafts never submitted may be omitted. Summary is `{exam:Draft,teacherName,subjectName,className,approvedVersion,packageState}`. Draft is unchanged BE-03. approvedVersion is positive integer or null. packageState is not_requested/pending/ready/failed.

GET /admin/exams/:id returns Summary plus `{items,serverNow,packageError,sessions,history}`. Items use BE-03 private schema, including supplied keys, labels, explanations, AI flags and teacher resolution notes. Return one coherent aggregate revision; for an approved exam return its frozen approved items. packageError is nullable and sanitized. Sessions use the shape below. History entries `{action,actorName,at,comment,revision}` are ordered oldest first; action submitted/returned/approved/scheduled/rescheduled. Preserve complete audit records in the database. No decryption secret appears in these responses. GET is read-only.

## Approval and return

POST /exams/:id/approve and POST /exams/:id/return accept `{revision,comment}`; comment is trimmed, nonempty, at most 2,000 characters. Both return complete AdminDetail after commit. Require current in_review status and matching aggregate revision. Approval recomputes validity, item totals, assignment context and all reviewed gates; missing review is 409 AI_REVIEW_REQUIRED. Lock against teacher edits/import/AI/submission. Freeze metadata, question wording/options, keys, marks, primary/secondary topics, explanations and review provenance in immutable approvedVersion 1 (increment for future explicit versions). Status becomes approved; increment draft revision and audit administrator/time/comment. Teacher must not mutate approved content.

Return records feedback, sets returned and increments revision; preserve the submitted snapshot and audit trail. BE-03 teacher reads expose returnComment; teacher corrections require explicit review of changed content before resubmission. Only in_review can be returned here; approved/active content cannot be silently reopened. Crossed approve/return requests must yield one winner and a revision conflict for the other. Replays cannot duplicate audit events or versions.

Approval queues durable package generation from the BE-02 allowlisted student schema only. packageState pending until the approved artifact is validated and ready; failure retains approval and a visible diagnostic, disables scheduling. Build from explicit fields, never delete secrets from a private entity serializer. Provider AI is not part of package generation. POST /exams/:id/package-retry `{revision}` is admin-only, idempotent, only for approved failed package jobs; return AdminDetail. Persist job identity/lease/error and resume after restart. Poll reads report truthful state. A failed package must never make the paper schedulable. Session-specific encryption/preparation may derive from this approved artifact while preserving BE-02 generation/nonce rules.

## Scheduling and roster

POST /exams/:id/sessions accepts `{revision,approvedVersion,preparationVisibleAt,resultsReleaseAt}`. Require approved status, matching draft revision/version and ready package. Times are UTC ISO strings. preparationVisibleAt must be strictly after server now; no backdating to bypass the ten-minute preparation. Compute startsAt = preparationVisibleAt + 10 minutes; endsAt = startsAt + frozen durationMinutes. Require resultsReleaseAt at or after endsAt and every accommodated roster deadline. It is a planned release date, not publication authorization. Results remain hidden until separate administrator publication approval and recovery gates, even after this date. Practice remains disabled unless separately authorized; scheduling never enables it.

In the same transaction snapshot currently eligible active students in the approved class and their authorized accommodations. Reject an empty roster with 422 VALIDATION_ERROR. Persist membership, approvedVersion, exact timings, scheduleRevision 1, audit and package references before returning. Do not enroll anyone by visiting a URL. Store accommodations per member and BE-02 deadline/finalAcceptUntil rules. Rosters and accommodations remain immutable in this increment; later directory changes do not silently add/remove students or change deadlines. Repeated identical requests with the same key return the same session; serialize distinct creation requests and reject an overlapping session for the same exam/class including accommodated time. Multiple distinct nonoverlapping sittings are permitted; the UI requires an explicit additional-sitting action.

Session = `{sessionId,examId,approvedVersion,scheduleRevision,preparationVisibleAt,startsAt,endsAt,resultsReleaseAt,rosterCount,canReschedule}`. All revisions positive integers; count from snapshot. Return full AdminDetail, 201 first creation / 200 replay. Increment draft aggregate revision for session creation so stale concurrent scheduling cannot proceed. AdminDetail.serverNow is server clock UTC.

PATCH /sessions/:id/schedule accepts `{scheduleRevision,preparationVisibleAt,resultsReleaseAt,reason}`. Nonempty reason up to 2,000 characters. Require matching schedule revision, server now strictly before the OLD preparationVisibleAt, no attempts/packages issued and no active sitting; new preparation strictly in future. Lock same session gate as attempt creation and package issuance. Enforce approval/package/version, timing, accommodation and overlap constraints again. Keep the frozen roster/approvedVersion/duration; recompute start/end and every accommodated deadline, increment scheduleRevision and draft revision once, invalidate/regenerate any unissued schedule-specific artifacts and audit old/new values plus reason. No reschedule at or after old preparation, even if no one has joined. canReschedule reports this same permission. Errors 409 REVISION_CONFLICT; never extend an active attempt or revise downloaded packages. Return AdminDetail. Lost-response replay remains valid after preparation without repeating the mutation.

## Student linkage

Only snapshot-eligible students see the new sitting through GET /me/exams and detail, with BE-02 phases and independent attempt state. Approved content alone is not an assigned sitting. Before preparation no attempt/package; before common start no key; deadline never resets for late joining. Deliver precisely the approved paper, instructions, marks and question ordering. Generate shuffled question/option orders once per attempt and retain them on retries/transfer. Keys, explanations, flags and teacher notes must never enter official plaintext. Exact final receipt rules remain unchanged.
