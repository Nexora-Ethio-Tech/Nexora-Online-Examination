## Wire contract

All routes use /api/v1, cookie authentication, Origin and CSRF protections from the main contract. Every POST/PATCH below requires Idempotency-Key (UUID). Authenticate and authorize before idempotency lookup. Scope keys to school, teacher and operation, store canonical payload hash and original response durably; replay an identical request before checking its old revision. Changed payload with the same key is 409 REVISION_CONFLICT. Multipart identity uses examId, integer revision and SHA-256 of raw file bytes (plus source filename). No second upload or AI job on replay. Retain records for the lifetime of the draft/review history.

GET /me/teaching-assignments?limit=100&cursor=... returns `{items:[{assignmentId,subjectName,className}],nextCursor}`. Each assignment is one valid class/subject pair for this teacher; derive grade and school server-side. Never accept arbitrary subject/class combinations. GET /exams?limit=25&cursor=... returns `{items:[Draft],nextCursor}` ordered by creation time descending, examId descending; teacher sees only their owned exams within current assignments. Same cursor conventions apply to assignments (assignmentId ascending). Honor pagination, return null when exhausted.

Metadata = `{title,instructions,assignmentId,language,durationMinutes,passPercent,ordering}`. language en/am; ordering fixed/shuffle_questions_and_options; passPercent inclusive 0–100; duration 1–480 integer minutes. See schema for field lengths. These are initial technical bounds, not license quotas.

Draft = Metadata plus `{examId,revision,status,totalMarks,itemCount,reviewedCount,importId,returnComment}`. Revision starts at 1, positive integer. status draft/in_review/approved/returned. importId and returnComment nullable. Counts and totalMarks calculated from persisted items, never client claims. Pass threshold is percentage, not raw marks. GET /exams/:id returns Draft. POST /exams creates Metadata draft, 201 (200 replay). PATCH /exams/:id accepts Metadata plus revision; returns Draft. Assignment/language cannot change after successful import; create another draft for a different context. Other metadata changes require current revision and invalidate no question review because they do not change question semantics; approval always freezes all metadata and content.

GET /exams/:id/items returns `{revision,items:[Item]}` for the same aggregate revision. Item exact fields are in schemas.ts: stable itemId, externalId, type, stem, options [{id,text}], correctOptionId, marks, primaryTopic, secondaryTopics, explanation, keyConsistent (boolean/null), reviewFlags (strings), reviewed, reviewNote. All keys/explanations are private teacher/admin content. True/false options are true/false, text True/False; MCQ option IDs A/B/C/D for populated template columns. Require at least A and B, contiguous nonempty options, unique external IDs. No HTML rendering.

PATCH /exams/:id/items accepts `{revision,item}` and returns updated Draft. Match existing itemId and immutable externalId/type/option IDs; validate every field including correctOptionId membership. Teacher may correct wording, option text, marks, key, topic and explanation using a plain form. AI-owned keyConsistent/reviewFlags must equal stored values; teacher resolves flags using a nonempty reviewNote, never deletes the evidence. Reviewed=true requires primaryTopic and explanation, plus resolution note if flagged or keyConsistent=false. Save review with the exact edited content and reviewer/time. A content/key correction invalidates old AI input hash, retains prior suggestion provenance, and requires explicit review of the corrected explanation; do not apply stale AI later. Never let AI mutate a key.

POST /imports: multipart/form-data fields examId, revision (decimal integer text), file (one binary file). Browser supplies boundary; do not require JSON. Maximum 5 MiB compressed, 200 items, 25 MiB total expanded ZIP, 1,000 entries, no encrypted ZIP, traversal, external relationships, macros, images, formulas, embedded objects, merged or nested tables. Detect OOXML type by contents, not suffix/MIME alone. Stream with bounded limits; reject oversized upload 413. Create private source with random path, hash and durable queued job atomically against revision; 202 Job. Only one nonterminal job per exam. Starting import increments revision; refuse edits/submission while queued/parsing/ai_queued/ai_running. Existing items remain until a complete valid replacement parses, then replace atomically and reset all reviews. Failed parsing leaves previous items unchanged. Reject partial imports; retain every row/field diagnostic. UI warns that replacing a valid paper resets its review.

Templates: XLSX one Questions worksheet; DOCX one simple table. Exact headers external_id,type,question,option_a,option_b,option_c,option_d,answer,marks. XLSX header row 1 / DOCX table row 1; diagnostic row 2 is first question. mcq_single key A/B/C/D must reference populated option; true_false key TRUE/FALSE, all option cells blank. Positive integer marks. Unicode text preserved. Reject unsupported content rather than dropping it. Permit plain introductory paragraphs outside the DOCX table (the supplied example has instructions), document-property thumbnail metadata and formatting-only empty XLSX cells beyond the data rectangle; these are not question content. Reject embedded question images or meaningful data outside the template. The distributed example files and docs/fixtures/teacher-import-v1.json must produce identical items. Its two rows total four marks with B and TRUE keys; the separate BE-02 ten-question fixture still tests student delivery.

Job = `{importId,examId,state,parsedCount,completedCount,sourceName,sourceSha256,failure,diagnostics:[{row,field,message}]}`. States queued/parsing/ai_queued/ai_running/ready/failed; counts report actual persisted progress (never estimated animation); failure nullable readable message. GET /imports/:id returns Job. Parse failures use failed + diagnostics; async AI failures retain parsed draft and failure, completedCount may be partial. Backend GET has no job side effects. Frontend polls every 2 seconds while active, refreshes draft/items after job transitions. Every item-changing job commit increments aggregate revision, protecting stale editors.

POST /imports/:id/ai-retry `{revision}` returns 202 Job. Only latest import, failed with persisted parsed items, no active job, mutable draft/returned state. Preserve reviewed items; retry unfinished/unreviewed items only. Durable workers with leases, two concurrent calls initially, 30-second timeout, at most two retries, budget and usage tracking; restart recovery via protected cron. Store provider/model/prompt/input hash/taxonomy revision/token usage/failure. AI inputs contain questions, teacher keys, subject/grade/language/topic names only. Strict structured output; normalize topics, flag inconsistency; do not change answers or fabricate fallback AI. Cache within school only. Invalid/stale provider output cannot overwrite current edits. Staff can manually complete/review after AI failure; real-model acceptance still required.

POST /exams/:id/submit-for-approval `{revision}` returns Draft with status in_review and incremented revision. Require at least one item, all items valid and reviewed, no active job, valid assignment and metadata. Recompute totals; freeze submission snapshot and audit reviewer/content revision. Missing reviews return 409 AI_REVIEW_REQUIRED; stale revision/busy/immutable state return 409 REVISION_CONFLICT. No teacher editing after submission or approval. Administrator return supplies returnComment and makes returned mutable; resubmission must cover changed content. Teacher must never approve, schedule, publish or release practice through these endpoints. Approval freezes a separate approved version, compatible with BE-02 student allowlist; no key/explanation leakage.

## Security and acceptance

Enforce teacher ownership, current assignment and school on every read/write/job/template-private download. Cross-school/other-owner IDs return 404, wrong role 403; students cannot read any keys. Transactional aggregate revision locks serialize edits, import replacement, AI completions and submit. Sensitive responses no-store. Keep files outside public storage. No private contents in logs. Public example templates contain synthetic data only.

Required tests: both real templates parse to exact fixture; Unicode and true/false preserved; duplicate IDs/missing answer/noninteger marks/invalid choice produce row diagnostics; malformed ZIP, expansion bomb, formulas, external relationships, images, macros and unexpected sheets/content rejected with bounded resources. Failed replacement preserves original draft. AI failures/restarts retain source/items and truthful progress; retry cannot alter reviewed data; prompt injection remains data; stale AI cannot overwrite teacher corrections. Real provider produces one reviewed explanation in each supported language. Role/tenant/assignment tests cover every route. Duplicate create/upload/edit/submit after lost response and process restart has one effect; changed-key-payload and stale revision conflict. Concurrent edit/AI/import/submit yields one coherent reviewed snapshot. Teacher cannot bypass admin authority. Counts/marks match imported data and frontend preview.
