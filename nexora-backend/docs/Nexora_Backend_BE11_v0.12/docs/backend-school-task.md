## 1. Authority, common behavior and persistence

All directory routes below are school_admin only after completed MFA. Use /api/v1, cookie sessions, server-derived school, Origin/CSRF, private/no-store and common errors. Every mutation requires a UUID Idempotency-Key scoped to school/actor/path/method, a trimmed 1–2000 character audit reason, and expected revision for edits. 401 for anonymous/incomplete MFA; 403 for wrong role; 404 for foreign/unknown resource; 409 REVISION_CONFLICT for stale revision, duplicate identity or incompatible state; 422 for field validation. Return safe details with field paths. Reject unexpected privilege/role/school/password fields. Never accept schoolId from the client.

Use relational school-bound classes, subjects, users, enrollments and teacher assignments; Argon2id password hashes with individual salts; globally unique readable school-prefixed login IDs. Student roster reference is unique per school and distinct from loginId. No email requirement. Teacher/student roles are immutable here. Operator provisioning and first-admin MFA recovery remain BE-02 protected operations, not browser account creation or admin bypass.

Default list limit 25, range 1–100, opaque scope/filter-bound cursors; include serverNow and nextCursor. Stable ordering by ID, audit newest first then ID. Search is a literal case-insensitive substring of displayName/loginId/studentRef, max 160 characters, never a query expression. Return all records through pagination; request/import size limits are not school/student quotas. All GETs are read-only and never return passwords or password hashes.

## 2. Classes, subjects, accounts and assignments

- GET/POST /classes; PATCH /classes/:id. Create `{name, academicYear, reason}`; edit adds `{revision, active}`. Class names are unique within school/year after whitespace/case normalization. Return classSchema. Archive is reversible; reject archiving a class with active enrollments, active assignments or referenced exam drafts/sittings. Renaming must preserve IDs and frozen historical snapshots.
- GET/POST /subjects; PATCH /subjects/:id. Create `{name, code, reason}`; edit adds `{revision, active}`. Code is 1–30 ASCII letters/digits/_/-, case-insensitively unique within school; name 1–160. Return subjectSchema. Reject archiving while active assignments or exams reference it.
- GET /students and GET /teachers support `search`, `limit`, `cursor`; return pageSchema(accountSchema). User rows contain metadata only: userId, displayName, loginId, role, studentRef/classId (null for teachers), active/inactive status, unissued/issued credentialState and revision. Do not include administrators in these endpoints.
- POST /teachers `{displayName, reason}` creates an active teacher, login ID and initial random password, returning credentialIssueSchema. Teacher creation and issuance commit together.
- PATCH /students/:id or /teachers/:id accepts accountEditSchema. Student classId must reference an active class; teacher classId must be null. Preserve studentRef/loginId/role. Enrollment changes apply to future roster snapshots; never modify an existing sitting's roster, attempts, answers, receipts or historical results. Deactivation revokes every current auth session immediately; reactivation does not resurrect them. An active account is still required for exam authorization. Audit all edits and warn in the UI that deactivation interrupts access.
- GET/POST /teacher-assignments; PATCH /teacher-assignments/:id. Create `{teacherId, classId, subjectId, reason}`, active referenced entities only. A duplicate active triple conflicts; reactivate its original record instead of duplicating. Edit `{revision, active, reason}` changes availability only. Return assignmentSchema with resolved names. Reject deactivation when existing exam records depend on that assignment in this MVP; preserve historical ownership. Teachers cannot edit assignments.
- GET /me/teaching-assignments keeps the BE-03 DTO and returns only the authenticated teacher's active, valid assignments, paginated. BE-03 creation/writes recheck this scope; BE-05 teacher reads/exports recheck authorized assignment scope. Never grant another teacher's papers merely because they know an ID.
- GET /admin/directory-audit returns paginated auditSchema rows: auditId, action, target, targetLabel, actorName, reason, at. targetLabel is a human-readable snapshot of the affected class/subject/login ID or assignment; issue audits must retain the affected account IDs without secrets. Persist immutable actor/school/target IDs too. Do not log credential content or include it in reasons/errors/traces.

## 3. CSV preview and atomic import

POST /students/import uses multipart `{file, classId}` plus idempotency key. File must be UTF-8 CSV, optional BOM, maximum 2 MiB per upload and 2,000 records per import; support RFC-style quoted commas, escaped quotes and CRLF/LF. Header is exactly `studentRef,displayName`. StudentRef is 1–64 ASCII letters/digits/_/- and is case-insensitively unique per school; displayName is trimmed 1–160 Unicode characters. Reject malformed syntax/headers or oversized uploads. Validate every row and report field-specific errors, duplicate references in the file, and references already in this school. Do not silently merge/overwrite existing people. Duplicate names are permitted with different references. Blank trailing lines are ignored. A separate import can add more students.

The response is previewSchema: importId, revision (starts at 1), classId/className, expiresAt (30 minutes), all bounded rows `{row,studentRef,displayName,errors:[{field,message}]}`, canCommit, totalRows. Row is the CSV logical record number including header as row 1. Preview creates no users, enrollment or credentials. Store sanitized preview privately with actor/school/class revision, file digest and expiry. Errors in any row make canCommit false. No execution of uploaded formulas, HTML or instructions.

POST /students/import/:id/commit `{revision,reason}` with a fresh retained key returns importResultSchema `{importId,createdCount,userIds}`. Require owning actor/school, valid expiry, matching preview/class revision, active class and all rows valid. Revalidate uniqueness and scope inside the transaction. Commit every account/enrollment or none; a concurrent import conflict creates no partial roster. Assign unique login IDs, status active, credentialState unissued, no usable password/hash until issuance. Idempotent commit/replay returns the original result even after preview expiry, without duplicate accounts. Commit once per preview even with different keys. Previewing or importing never changes already frozen session rosters.

## 4. One-time credentials and password reset

POST /students/generate-credentials `{targets:[{userId,revision}],reason}` accepts 1–500 distinct active, unissued students in this school. Initial issuance must not rotate already-issued passwords. Atomically validate every target, generate independent cryptographically random passwords with at least 128 bits of entropy, hash them, increment each account revision and mark issued. Return credentialIssueSchema `{issueId,issuedCount,issuedAt,accounts:[{userId,displayName,loginId}],credentials:[{userId,displayName,loginId,password}]}`. All-or-nothing validation; audit the issue metadata without plaintext. Teacher creation uses this same response shape for one teacher. accounts and credentials contain matching unique user IDs on first success; issuedCount equals their lengths. accounts remains present on metadata-only replay so staff can locate every affected login ID.

POST /students/:id/reset-password and /teachers/:id/reset-password `{revision,reason}` generate one fresh password, replace its hash, increment revision, mark issued and revoke all existing auth sessions in the same transaction. Require an active same-school target. Reset must not erase device enrollments, pending IndexedDB work, final snapshots, receipts or recovery evidence. Existing browser 401/relogin behavior preserves local pending answers. Resetting student/teacher credentials does not reset admin MFA or create admin access.

**Explicit one-time response exception to common idempotency replay:** persist only successful issue metadata (including affected account identities) and a canonical request fingerprint; never persist plaintext passwords in the replay table. First successful request returns credentials. Every later replay returns the same issueId/count/time/affected account identities but `credentials: null`; it never generates again or retrieves old passwords. Different payload under the same key conflicts. Concurrent identical requests have one credential-generating transaction. After a lost first response, the metadata replay proves issuance but cannot recover passwords; instruct the administrator to reset affected accounts. Do not automatically reset on network failure. This choice preserves the master plan's hash-only storage requirement.

The frontend holds returned credentials only in component memory, with no query/mutation cache persistence, browser storage or logs. It offers one deliberate CSV download and a review acknowledgment before closing. Navigating/signing out discards that memory; warn before leaving while visible. Reload cannot retrieve credentials. CSV cells must be escaped against spreadsheet formulas (leading whitespace/control before =,+,-,@ included), quoted, and UTF-8; credential filenames contain no names/passwords. Private distribution is a staff action outside this app. Credential download does not send email/SMS. The server must not log response bodies for these operations.
