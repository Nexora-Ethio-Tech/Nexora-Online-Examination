# BE-10: Extra-time accommodations

Issued 15 October 2026, contract v0.11. Mandatory implementation instructions, not a request for backend approval. Master plan v3.0 p.10 requires approved extra time fixed before preparation. The routes, wire fields, 480-minute input ceiling and revision rules here are project implementation decisions supporting that requirement; they are not quotations from the master plan.

## Scope and exact interfaces

Implement the executable schemas in `src/features/exams/admin/accommodation-schemas.ts`, the revised `sessionSchema` and history action in `src/features/exams/admin/schemas.ts`, and calls in `src/features/exams/admin/api.ts`. Prefix all paths with `/api/v1`. Retain the existing opaque-session, active-school-membership, admin MFA, CSRF, Origin, error envelope and Idempotency-Key conventions. Reject unauthorized access before reading a replay. Teachers and students cannot read or edit this administrator roster.

1. `GET /admin/sessions/:sessionId/accommodations?limit=25&cursor=...`: return `{session,items,nextCursor,serverNow}`. `session` contains all BE-04 sitting fields plus `title`, `latestDeadlineAt`, `canEdit`. Items contain `studentId,loginId,studentName,extraMinutes,deadlineAt,lastChange`. Last change is null initially, otherwise `{auditId,actorName,at,reason,previousExtraMinutes,extraMinutes}`. Use stable student ordering and an opaque cursor tied to the school, sitting and schedule revision; reject stale cursors with 409 REVISION_CONFLICT. Never silently mix pages from different revisions. Counts and latest deadline cover the entire roster, not only the returned page. GET creates no attempt, package delivery or student activity. Send private/no-store responses.
2. `PATCH /sessions/:sessionId/accommodations`, UUID Idempotency-Key: body `{scheduleRevision,studentId,extraMinutes,reason}`. Whole extraMinutes is 0–480 inclusive; zero removes the allowance. Reason is trimmed, nonempty, at most 2000 characters. Reject no-op changes. Return `{session,student,serverNow}` using the above schemas. Server derives every deadline; do not accept a deadline or school ID from the client.
3. Every BE-04 session object in admin detail/scheduling responses now requires `latestDeadlineAt`, even with no accommodations (then equal to endsAt). History adds `accommodation_changed`. These are the only existing wire-shape changes. Student/attempt/monitor wire shapes are unchanged; their deadline values must reflect the accommodation.

## Transaction and freeze rules

The scheduled student membership remains frozen at scheduling. This increment explicitly supersedes BE-04's earlier immutable-accommodation restriction only to permit audited edits to that sitting's student allowances strictly before preparation. Existing approved allowances must be preserved on migration and schedule creation; do not silently replace them with zero. Students without an allowance receive zero. No directory change adds/removes students from an existing roster.

Lock the sitting and affected roster row in one transaction shared with reschedule, preparation/attempt creation, publication and practice changes. Recheck ownership, current scheduleRevision, approved/package-ready state and server time. Require server time strictly less than preparationVisibleAt and no attempt/package issuance for the sitting. Reject at the exact preparation boundary, even if the administrator opened the form earlier. Reject while practice is enabled or after content release. Recheck the time at the mutation's serialization point. Never extend an active attempt or permit editing by moving preparation backwards/forwards after its original cutoff.

Compute `deadlineAt = endsAt + extraMinutes * 60 seconds`; `latestDeadlineAt = max(endsAt, all frozen student deadlines)`. Common startsAt/endsAt never change during an accommodation edit. Require planned resultsReleaseAt at or after latestDeadlineAt. Otherwise return 409 RESULTS_TIME_CONFLICT and instruct the administrator to move planned results through existing Change schedule first. Do not silently change results time. Preserve existing overlap restrictions and use the latest accommodated deadline as the end of the occupied window; reject conflicts with 409 SCHEDULE_OVERLAP. Do not broaden the existing scheduling overlap policy to unrelated papers/classes.

On success atomically update the allowance, increment scheduleRevision and the aggregate exam revision, persist the audit and the immutable replay result. Audit retains school, sitting, student, actor, UTC time, reason, old/new extra minutes, old/new deadlines, schedule revisions and request identity. The roster exposes its last change; BE-04 history records every change. Preserve historical records even after a later edit/removal or reschedule.

Replay the identical committed payload/key with its original response, including after preparation opens. Do not run the cutoff/revision checks before checking an authorized committed replay. Different payload with the same key returns 409 REVISION_CONFLICT. Authentication/authorization still precedes replay. Enforce uniqueness atomically across backend processes and restarts. Unknown outcomes must be resolvable by retrying the same key; retain replay data for the existing mutation retention period. Standard network/server failures must not imply that a transaction did not commit.

Errors: 401 for missing/expired session; 403 for wrong role/MFA; 404 NOT_FOUND for inaccessible sitting or a student outside its roster; 422 VALIDATION_ERROR for invalid fields/no-op; 409 REVISION_CONFLICT for stale revision/cursor or mismatched replay; 409 ACCOMMODATIONS_LOCKED for preparation/delivery/practice freeze; the two explicit conflict codes above for results/overlap. Return the existing structured envelope and useful field details. Frontend validation is not authorization.

## Required downstream behavior

- BE-04 reschedule preserves each student's extra minutes and recalculates personal/latest deadlines from the new common end. Reject planned results or overlaps against that latest deadline. Preserve roster and enforce the original preparation/delivery lock.
- BE-02 list/detail and attempt creation use the frozen individual deadline. A student joining after common end but before their extended deadline can still enter under normal eligibility/device rules. A late join never earns a fresh duration. Attempts carry the new scheduleRevision and `finalAcceptUntil = deadlineAt + 5 seconds`. Unlock, saves, final receipt, recovery, reload and device transfer preserve those values.
- BE-09 monitor shows each individual deadline and the entire roster's latest deadline, including absent students. Counts/phases must not mark an accommodated student ended at the common end. Do not expose approval reasons on student screens.
- BE-05 publication must wait until the entire roster's maximum finalAcceptUntil, including students without attempts. An accommodation/schedule change invalidates candidate revision snapshots; it never edits an already released publication.
- BE-07 practice waits for every related sitting's full accommodated submission window and the existing publication/admin gates. Early submission or an absent student must not shorten that window.
